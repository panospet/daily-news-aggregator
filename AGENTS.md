# AGENTS.md — daily-news-aggregator

Guidance for AI agents and humans working in this repository.

## What this repo is

A self-hosted news aggregation and summarization stack:
- **Miniflux** (RSS reader) stores raw articles in Postgres (with pgvector).
- **Go dashboard** (`cmd/server`) queries Miniflux's DB, clusters articles via the **Python AI service** (`ai/main.py`: fastembed + spaCy + cosine clustering), caches the clustered view in Redis (`ai_cache`, DB 0), and exposes an HTMX UI + JSON APIs.
- **Briefing News Producer**: pre-generates grounded Greek news summaries for the `audio-briefing` pipeline.

## Pipeline Context

This repository is the news provider in a small pipeline:
- **`audio-briefing`**: primary consumer. Twice daily (`07:45` & `19:45` Athens) this service pre-summarizes the top 20 story groups and saves them to Redis (`briefing_news:<slot>`). `audio-briefing` reads them via `GET /api/briefing-news?slot=morning|evening` (with on-demand fallback `POST /api/briefing-news/generate`).
- **`voice-service`**: available on `127.0.0.1:8002` for on-demand article speech synthesis.

## Ports & Routing

| Port | Service | Auth | Notes |
|---|---|---|---|
| 8080 | Go dashboard (HTMX + JSON APIs) | HTTP Basic | Main server |
| 8001 | Python AI service (`ai/`) | Internal | FastEmbed multilingual clustering |
| 6379 | Redis (bind 127.0.0.1) | None local | `ai_cache`, `summary_cache`, `briefing_news` |
| 5435 | Postgres (Miniflux DB) | Password | Mapped from container 5432 |

The dashboard can be exposed publicly behind any reverse proxy or Cloudflare Tunnel (`cloudflared-newspaper`, token-managed in compose). Do not change ports without updating both the compose file and the proxy ingress.

## Egress Proxy (optional)

Miniflux and Flaresolverr can route RSS downloads through an HTTP egress proxy:
- `cloudflared-client` runs a Cloudflare Access TCP tunnel to a remote proxy host (`CF_ACCESS_HOSTNAME` in `.miniflux.env`).
- Miniflux is pointed at it via `PROXY_URL=http://cloudflared-client:8888`; Flaresolverr via `PROXY=http://cloudflared-client:8888`.
- To fetch feeds directly (no proxy), remove the `cloudflared-client` service and drop the `PROXY_URL`/`PROXY` settings.

## Redis Cache Layers

1. **`ai_cache`** (TTL 60 min): full clustered dashboard dataset, kept warm by `StartBackgroundRefresh` (90s initial delay).
2. **`summary_cache`** (TTL 60 min): generated summaries keyed by `category:group_id`.
3. **`briefing_news:<slot>`** (TTL 14 h): pre-generated speech-ready news blocks for `audio-briefing`.
4. **`group_mapping`**: persistent topic-group IDs across clustering refresh cycles.

## Summarization & Anti-Hallucination Pipeline

Summaries are generated by `internal/summarize`:

1. **Enrichment** — articles with <60 words of stored content are fetched live and their full page text extracted (`extract.go`).
2. **Stub filter** — articles still under 50 words are dropped.
3. **Grounded prompt** — sources numbered `[1..n]`; the prompt forbids inventing facts and requires inline citations.
4. **Verification** (`verifyGrounded`) — a summary is rejected when it has no citations, cites out-of-range sources, or contains multi-digit numbers absent from every source. Returns HTTP 422 on rejection.
5. **Speech cleaning** — citations like `[1]` are stripped for `audio-briefing`.

Keep all stages intact, keep tests green (`go test ./internal/summarize/`), and prefer rejecting a summary over displaying an unverified one.

## Audio Briefing Pre-Generation (`internal/handler/briefing_news.go`)

- Scheduled via `StartBriefingPregen` at `07:45` (morning) and `19:45` (evening) Athens time.
- Selects top N groups (default 20) via `topView()`.
- Parallel grounded summarization bounded to 5 concurrent workers (`maxConcurrent`).
- Total LLM failure fallback: titles-only block so `audio-briefing` never crashes.
