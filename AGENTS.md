# AGENTS.md — daily-news-aggregator

Guidance for AI agents and humans working in this repository.

## What this repo is

A self-hosted news aggregation and summarization stack:
- **Miniflux** (RSS reader) stores raw articles in Postgres (with pgvector).
- **Go dashboard** (`cmd/server`) queries Miniflux's DB, clusters articles via the **Python AI service** (`ai/main.py`: fastembed + spaCy + cosine clustering), caches the clustered view in Redis (`ai_cache`, DB 0), and exposes an HTMX UI + JSON APIs. The dashboard is the main frontend at **https://newspaper.panos.pet**.
- **Briefing News Producer**: Pre-generates grounded Greek news summaries for the `audio-briefing` podcast pipeline.

## The 4-Service Ecosystem Context

This repository is the news provider within the 4-service media and news stack:
- **`media-stack`**: Provides **Tinyproxy** (port `8888`), tunneled via Cloudflare Access (`tinyproxy.panos.pet`). Miniflux fetches external RSS feeds through this proxy via the local `cloudflared-client` service in `docker-compose.yml`.
- **`audio-briefing`**: Primary consumer of this service. Twice daily (`07:45` & `19:45` Athens time), `daily-news-aggregator` pre-summarizes the top 20 story groups and saves them to Redis (`briefing_news:<slot>`). `audio-briefing` reads this block via `GET /api/briefing-news?slot=morning|evening` (with on-demand fallback `POST /api/briefing-news/generate`).
- **`voice-service`**: Available as a microservice on `127.0.0.1:8002` for on-demand article speech synthesis.

`newspaper.panos.pet` → Cloudflare tunnel (`cloudflared-newspaper`, token-managed in compose) → `localhost:8080` (Go dashboard). Ingress rule is in the Cloudflare dashboard; do not change ports without updating both.

## Redis Cache Layers

1. **`ai_cache`** (TTL 60 min): Full clustered dashboard dataset. Kept warm by a background refresher (`StartBackgroundRefresh`) with a 90s initial delay (lets FastEmbed load before first clustering call).
2. **`summary_cache`** (TTL 60 min): Stores generated AI summaries keyed by `category:group_id`.
3. **`briefing_news:<slot>`** (TTL 14 hours): Pre-generated speech-ready news blocks for `audio-briefing`.
4. **`group_mapping`**: Preserves persistent IDs for topic groups across clustering refresh cycles.

## Summarization & Anti-Hallucination Pipeline

Summaries are generated by `internal/summarize`. The pipeline is:

1. **Enrichment** — articles with <60 words of stored content are fetched live and their full page text extracted (`extract.go`). Greek sites often serve RSS teasers of 20–40 words.
2. **Stub filter** — articles still under 50 words are dropped entirely: titles without facts are hallucination bait.
3. **Grounded prompt** — sources are numbered `[1..n]`; the prompt forbids inventing scores/names/dates not present in the sources and requires inline citations like `[1]`.
4. **Verification** (`verifyGrounded`) — a summary is rejected when it has no citations, cites out-of-range sources, or contains multi-digit numbers (scores, years) absent from every source article. The handler returns HTTP 422 with a friendly Greek message on rejection.
5. **Speech Cleaning**: Citations like `[1]` are stripped from the final summary returned to `audio-briefing` so speech synthesis flows naturally.

When touching this code: keep all stages intact, keep tests green (`go test ./internal/summarize/`), and prefer rejecting a summary over displaying an unverified one.

## Audio Briefing Pre-Generation Pipeline (`internal/handler/briefing_news.go`)

- Scheduled via `StartBriefingPregen` at `07:45` (morning) and `19:45` (evening) Europe/Athens time.
- Selects top N groups (default 20) using `topView()`.
- Runs parallel grounded summarization bounded to 5 concurrent workers (`maxConcurrent`).
- Total LLM failure fallback: Generates a titles-only block so `audio-briefing` never crashes.
