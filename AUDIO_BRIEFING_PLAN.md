# Automated Personal Daily Audio Briefing & Music Playlist Pipeline — Implementation Plan (v2)

> Status: **Plan / proposal** (not yet implemented).
> **v2 changes:** service rewritten in **Go** (was Python stdlib); news is now **pre-generated by the daily-news dashboard** (see `BRIEFING_NEWS_PLAN.md`) and read over HTTP; the service is **deployed in media-stack compose** (host network + music volume mount) rather than daily-news.
>
> Companion docs: `daily-news-aggregator/BRIEFING_NEWS_PLAN.md` (news producer) · `media-stack/` (Navidrome + library).

---

## 1. Goals

Build an orchestration service that, twice a day (08:00 and 20:00 Europe/Athens):

1. Reads a pre-generated **news block** (top stories + grounded summaries) from the daily-news dashboard over HTTP.
2. Converts each news summary to Greek speech with the `edge-tts` Go library (female anchor voice).
3. Selects 10 music tracks by **shuffling** the 2026-release albums in Navidrome, picking the "most famous" track per album via Last.fm.
4. Announces each track (title + artist) via TTS (male voice).
5. Normalizes **speech only** with ffmpeg `loudnorm`; music is transcoded to MP3 192 kbps without loudnorm.
6. Publishes an ordered playlist (JSON) of alternating `news → track-intro → music` items plus a web player page that plays them sequentially.

Retention: keep 30 days of generated briefings.

  │   -news      │         │

**Why Go:** matches the user's preferred language; reuses the same ecosystem as the dashboard; `edge-tts` has actively-maintained Go ports; ffmpeg runs via `os/exec`. No Python runtime or pip dependencies.

**Why read news over HTTP instead of Redis:** the dashboard already pre-generates grounded summaries (see `BRIEFING_NEWS_PLAN.md`) and exposes them as a single "news block" endpoint. The briefing service stays a pure consumer with one data path (HTTP), and never learns the Redis or `ai_cache` format.

## 3. Data fetching strategy

### 3.1 News (pre-generated block)

- `GET {DASHBOARD_URL}/api/briefing-news?slot=morning|evening` with basic auth (`AUTH_USERNAME`/`AUTH_PASSWORD`).
- Response is a JSON array, speech-ready: `[{"topic":"…","summary_text":"…"}, …]` (top-20 from the producer; citations already stripped, plain text).
- Take the first `NEWS_SEGMENTS` (10) items.
- **No** summarization, HTML stripping, or Redis access happens in this service.
- On failure (dashboard down / 422 / auth error): retry with backoff; if still down, **skip news** and publish a music-only briefing (or reuse the previous briefing's news — configurable), log the failure, never crash the run.

### 3.2 Music (2026 releases, shuffled)

- **Discovery (Navidrome HTTP):**
  - `getAlbumList2` with `type=byYear&fromYear=2026&toYear=2026` (fallback: `type=newest&size=200` then filter albums whose `year` is 2026, or folder name contains `(2026)`).
  - **Shuffle** the album pool, take the first `MUSIC_TRACKS` (10) **distinct** albums.
- **Track selection per album:**
  - `getAlbum(id)` → list of songs.
  - Pick "most famous": Last.fm `artist.getTopTracks` (limit 50) → match names (case/accent-insensitive), first match wins.
  - Fallback chain: highest `playCount` among the album's songs → first song.
- **Audio (direct disk read):**
  - Navidrome's `getSong` returns `path` (relative to its music root). Open `MUSIC_ROOT + "/" + path` directly — no HTTP download, no filesystem coupling beyond the volume mount.
  - Transcode to MP3 192 kbps with ffmpeg (FLAC/any → MP3). **No loudnorm** on music.
  - Store as `music_<n>.mp3`.

> No repeat-tracking needed: a shuffle over a large pool is sufficient variety (per user decision).

### 3.3 TTS (edge-tts Go library)

- Use a maintained Go port of `edge-tts` (e.g. `raffleberry/edge-tts-go` or `difyz9/edge-tts-go`); pin it, and be prepared to swap if Microsoft changes the handshake.
- **Two voices, split by role:**
  - News: `el-GR-AthinaNeural` (female anchor) — `TTS_VOICE_NEWS`.
  - Track intro: `el-GR-NestorasNeural` (male) — `TTS_VOICE_INTRO`.
- **Chunk long text** at ~2000 characters before synthesizing (edge-tts stalls/truncates on very long inputs). Concatenate chunks per segment.
- Retry with backoff (3 × 1s/2s/4s) on transient failures.
- News text = the block's `summary_text` (already plain + citations stripped).
- Intro text = `Επόμενο κομμάτι: <title> από <artist>.`

### 3.4 Normalization & transcoding

- **Speech (news + intro):** ffmpeg one-pass `loudnorm=I=-16:TP=-1.5:LRA=11`, output 44.1 kHz stereo MP3 192 kbps.
- **Music:** transcode-only to MP3 192 kbps (44.1 kHz stereo). **No loudnorm** — music is already mastered to a consistent level, and loudnorm would degrade dynamics.

## 4. Playlist compilation logic

```
def generate(slot) -> Briefing:
    news  = fetch_news_block(slot)          # HTTP, take NEWS_SEGMENTS
    tracks = select_music(MUSIC_TRACKS)     # Navidrome + Last.fm + disk read

    n = min(len(news), len(tracks))         # cap-and-interleave (option A)

    items = []
    for i in range(n):
        news_path = tts(news[i].summary_text, f"news_{i}", voice=NEWS)
        news_path = normalize(news_path)
        items.append(news item)

        if TRACK_INTROS:
            intro_path = tts(f"Επόμενο κομμάτι: {tracks[i].title}…", f"intro_{i}", voice=INTRO)
            intro_path = normalize(intro_path)
            items.append(intro item)

        music_path = transcode(tracks[i])   # disk read → MP3 192 (no loudnorm)
        items.append(music item)

    write playlist.json + index atomically
```

**Cap-and-interleave:** news count == music count == `n`. If either side is short, the briefing simply has fewer segments (never orphan segments, never a crash from index mismatch).

**Scheduling:** internal ticker wakes every 60s. It fires a slot if the slot time has passed, it is still the same day, **and the output folder does not already exist** (filesystem is the durable "already generated" flag — restart-safe). This gives a same-day catch-up window (e.g. a brief outage at 08:00 still produces the briefing at 08:05). Manual `POST /api/generate` also supported; system crontab `curl` as fallback.

**Concurrency guard:** a lock prevents overlapping runs; `/api/status` reports `idle|running|error`.

**Durations:** computed via `ffprobe` (seconds) so the frontend shows progress and auto-advances accurately.

## 5. Storage & retention

- Base dir: `/media/panos/Moof/audio-briefing/` (configurable `AUDIO_BASE_DIR`).
- Layout:
  ```
  audio-briefing/
    2026-11-06/
      morning/
        playlist.json
        news_0.mp3, intro_0.mp3, music_0.mp3, ...
      evening/
        playlist.json
        ...
    latest.json   # points to most recent briefing folder
  ```
- `playlist.json` schema:
  ```json
  {
    "slot": "morning",
    "created": "2026-11-06T08:02:11+02:00",
    "items": [
      {"id":"n0","type":"news","title":"...","url":"/audio/2026-11-06/morning/news_0.mp3","duration":42.3},
      {"id":"i0","type":"intro","title":"Track intro","url":"/audio/.../intro_0.mp3","duration":4.1},
      {"id":"m0","type":"music","title":"Song","subtitle":"Artist","url":"/audio/.../music_0.mp3","duration":183.5}
    ]
  }
  ```
- Retention: on each successful generation, delete briefing folders older than `RETENTION_DAYS` (30). Keep at least the latest.
- Atomic writes: write to a temp dir then rename, so a half-finished run never serves a broken playlist.

## 6. Backend API endpoints

Service listens on `AUDIO_PORT` (default `8380`), behind basic auth (reuse `AUTH_USERNAME`/`AUTH_PASSWORD`; can be dropped behind a private tunnel).

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/` | Web player page |
| GET | `/healthz` | Liveness |
| GET | `/api/briefings` | List available `{date, slot}` |
| GET | `/api/briefing?date=YYYY-MM-DD&slot=morning\|evening` | Playlist JSON (default: latest) |
| GET | `/api/latest` | Latest playlist JSON |
| POST | `/api/generate?slot=morning\|evening` | Trigger generation (async) |
| GET | `/api/status` | `{state, current_slot, last_run, last_error}` |
| GET | `/audio/<relpath>` | Serve audio file |

Audio serving uses Go's `http.ServeContent`, which handles HTTP `Range` natively for seeking. All audio is served from the same origin as the page, so basic-auth on media elements is seamless after the first page login.

## 7. Frontend web player spec

Single HTML page (Go `html/template`) + vanilla JS, no build step.

- Loads `/api/latest` (or a selected briefing from a dropdown).
- Renders playlist: icon per type (📰 news, 🎵 music), title, duration.
- Controls: Play/Pause, Prev/Next, seek bar, current/total time, volume.
- Auto-advance: on `ended`, play next item; highlight current.
- Keyboard: Space (play/pause), ←/→ (seek ±5s), N/P (next/prev).
- Resumes position in `localStorage` (briefing id + index + time).
- Briefing selector (date + slot) and a "Generate now" button (POST).
- Mobile-friendly responsive layout; dark theme.

## 8. Error handling

- **News block unavailable:** retry with backoff; if still down, publish music-only briefing (or reuse previous news, configurable); log; keep previous briefing as `latest`.
- **One music track fails (read/transcode):** skip it, continue; if fewer than `MUSIC_TRACKS` remain, the briefing is shorter (cap-and-interleave handles it).
- **edge-tts failure:** retry with backoff; on persistent failure skip that segment.
- **ffmpeg failure on speech:** keep the un-normalized clip (log warning) so the run still publishes.
- **Last.fm unavailable:** fall back to playCount/first-track selection.
- **Partial run:** atomic folder rename ensures no broken playlist is served; previous briefing remains `latest`.
- All errors logged to `logs/` and reported via `/api/status` + optional Telegram notification (reuse media-stack Telegram bot token).

## 10. Implementation phases

1. **Scaffold** — Go module, config loader, Dockerfile (install `ffmpeg`), healthz endpoint. *(~1 day)*
2. **News ingestion** — news-block HTTP client (basic auth, JSON decode, take N). *(~0.5 day)*
3. **Music ingestion** — Navidrome discovery client, Last.fm top-tracks matching, disk read + ffmpeg transcode. *(~2 days)*
4. **Pipeline + storage** — generator, cap-and-interleave, atomic folder writes, `playlist.json`, retention, scheduler (filesystem check + catch-up), `/api/generate`, `/api/status`. *(~2 days)*
5. **Web player** — HTML + JS sequential player, briefing selector, progress, resume. *(~2 days)*
6. **Integration** — add service to media-stack `docker-compose.yml` (`network_mode: host`, music volume `ro` mount), crontab fallback, README, end-to-end manual run. *(~1 day)*
7. **Tuning** — voice check (`--list-voices`), loudness targets, durations, edge cases. *(ongoing)*

## 11. Decisions made

- **Language:** Go (was Python stdlib). `edge-tts` via a maintained Go port.
- **News source:** pre-generated "news block" from the dashboard (`/api/briefing-news`), not Redis and not per-topic `/summarize` calls.
- **Music selection:** shuffle the 2026-release pool, 10 distinct albums; no repeat-tracking.
- **Music "most famous":** Last.fm per album, fallback playCount/first track.
- **Music audio:** read files from disk via mounted volume (`MUSIC_ROOT`); Navidrome HTTP used only for discovery.
- **Loudness:** `loudnorm` on speech only; music is transcode-only.
- **Playlist shape:** cap-and-interleave — news count = music count = the smaller of the two.
- **Voice split:** female (`AthinaNeural`) reads news, male (`NestorasNeural`) does track intros.
- **Deployment:** media-stack compose, `network_mode: host`, music volume mounted read-only, `ffmpeg` installed in image.
- **Scheduling:** filesystem-existence check + same-day catch-up window (restart-safe).
- **No audio stitching:** individual clips + playlist JSON; a stitched master can be added later with ffmpeg concat.
- **Auth:** basic auth on all endpoints (can be dropped behind a private tunnel).

## 12. Risks & mitigations

- **`edge-tts` (unofficial, best-effort):** Microsoft may change the handshake or throttle. Mitigate: pin an actively-maintained Go port, chunk text, retry with backoff, cache TTS by content hash, and be ready to swap the lib (it's small and self-contained).
- **Long runs** (music transcode dominates): run in a background goroutine, report progress via `/api/status`, never block HTTP requests.
- **Disk usage:** 30-day retention × ~20 clips × ~5 MB ≈ 3 GB max; monitor and alert if low.
- **Navidrome auth tokens in URLs:** not applicable — audio is read from disk; only discovery calls use auth, and those never reach the browser.
